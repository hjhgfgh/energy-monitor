## 四、如何运行

前置：MySQL 已启动，且已执行建库脚本。

```bash
# 1. 建库（首次执行）
mysql -uroot -p123456 --default-character-set=utf8mb4 \
      -e "SOURCE docs/schema.sql"

# 2. 打包
mvn clean package -DskipTests

# 3. 启动服务端（HTTP 8080 / 设备接入 TCP 9000）
java -jar em-server/target/em-server-1.0.0-SNAPSHOT.jar

# 4. 另开终端启动模拟器：<host> <port> <设备数> <上报间隔ms> [起始设备ID]
java -jar em-simulator/target/em-simulator-1.0.0-SNAPSHOT.jar 127.0.0.1 9000 3 500
```

浏览器或 curl 验证：
```
http://localhost:8080/api/devices
http://localhost:8080/api/devices/latest-data
http://localhost:8080/api/devices/1001/recent?hours=1&limit=10
http://localhost:8080/api/devices/1001/page?page=1&size=20
```

数据库密码通过环境变量覆盖，不必改配置文件：
```bash
set MYSQL_PASSWORD=你的密码
```

## 五、本阶段关键设计决策

1. **主键即协议设备ID**。`device.id` 直接取 1001-1005，不用自增，让协议层、存储层、
   接口层共用同一编号，省掉映射表。实体对应 `@TableId(type = IdType.INPUT)`。
   代价是新增设备须由接入方分配编号 —— 现实中设备出厂即带编号，本就如此。

2. **Netty IO 线程不执行 JDBC**。设备数据先入有界队列（10 万），由独立线程消费落库。
   否则一个慢 SQL 会阻塞整条 EventLoop 上的所有设备连接。队列满时丢数据并计数，
   因为监控数据允许少量丢失，但不能因存储故障导致设备全部掉线。

3. **单帧校验失败只丢帧、不断连**。工业现场线路干扰会导致偶发位翻转，
   若因此断连，设备端会陷入「重连—被踢」循环，反而放大故障。

4. **心跳 90 秒超时**（3 个心跳周期）。留两次丢包余量，避免网络抖动误判离线。
