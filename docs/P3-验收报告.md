# P3 验收报告 —— 微服务拆分 / Nacos / Gateway / JWT / Feign / Sentinel

> 阶段目标：把 P2 单体拆成微服务，接入 Spring Cloud Alibaba 全家桶（Nacos 服务发现、Gateway 路由、OpenFeign 调用、Sentinel 限流），并实现网关统一 JWT 鉴权。

## 1. 架构变化

```
P2（单体）                      P3（微服务）
┌──────────────┐    ┌────────────────────────────────────────────┐
│  em-server   │    │ em-gateway        :8090  路由/JWT/限流      │
│  全部职责     │ →  │ em-device-access  :8081  Netty:9000 + Kafka生产 │
└──────────────┘    │ em-data-process  :8082  Kafka消费/落库/告警/WS │
                    │ em-web-api       :8083  查询接口/登录/Feign  │
                    │ em-common                协议/实体/Mapper/JWT │
                    │ em-simulator             虚拟设备             │
                    └────────────────────────────────────────────┘
```

- 拆分原则：**按职责拆 4 个服务**（接入无状态、数据处理唯一写库方、web-api 只读），而不是把类平均分。
- Nacos 3.0.3 单机模式，**MySQL 外置存储**（`nacos_config` 库，10 张表），控制台 :8848 / :8080。

## 2. 端到端验证结果（全部通过）

| # | 验证项 | 结果 |
|---|--------|------|
| 1 | 服务注册 | Nacos 服务列表：4 个服务全部注册 |
| 2 | JWT 拦截 | 无 token 访问 `GET :8090/api/devices` → **HTTP 401** `{"code":4001,"message":"未登录或令牌缺失"}` |
| 3 | 登录签发 | `POST /api/auth/login` → code=0，返回 token（userId=1, role=ADMIN, 2h 有效） |
| 4 | 网关路由 | 带 token → 查到 5 台设备（网关→web-api→MySQL） |
| 5 | Feign 调用 | `GET /api/devices/online` → `{"count":3,"deviceIds":[1001,1002,1003]}`（web-api 经 Nacos 负载均衡调 device-access 的**运行时内存状态**） |
| 6 | Sentinel 限流 | 40 次连发：**HTTP 200 ×5 + HTTP 429 ×35**（QPS=5 精确生效），429 响应体为结构化 JSON `{"code":4029,"message":"请求过于频繁，请稍后重试"}` |
| 7 | 数据链路 | 模拟器 3 设备 → Netty 解析 → Kafka 双消费组 → 落库/告警/推送全通 |

## 3. 关键设计决策（设计要点）

1. **JWT 在网关统一校验，业务服务不重复实现**：网关全局过滤器校验签名后把 userId/role 写入请求头透传。设备侧是独立鉴权（设备密钥），不走用户 JWT——「用户身份」与「设备身份」是两套信任体系。
2. **Feign 的落点选了「跨服务获取运行时状态」**：设备在线状态只存在于 em-device-access 内存（连接表），数据库里没有，这是服务间调用最自然的场景，不是为调而调。
3. **Sentinel 在网关层限流**：网关是所有流量必经之路，越靠前拦越省资源。API 分组（device-query-api=5 QPS / auth-api=3 QPS）而非路由级，因为登录接口有 BCrypt 刻意慢计算，容量特征不同。
4. **限流阈值取小值**：为了可复现可演示。真实容量需压测后按 P99 回填。

## 4. 过程中发现并修复的缺陷（6 个）

| # | 缺陷 | 根因 | 修复 |
|---|------|------|------|
| 1 | 所有 Spring Boot 应用（含 Nacos console）起在随机端口 51797 | 环境注入了 `SERVER__PORT=51797`，Spring Boot relaxed binding 把 `SERVER__PORT` 解析为 `server.port` | 启动脚本统一清除该变量；**纠正了此前「PowerShell 参数要加引号」的错误结论** |
| 2 | Sentinel 被拦请求返回 HTTP 500 而非 429 | block handler bean 缺 `@Order(-2)`，`ParamFlowException`（网关限流底层是参数流控）被 Spring 兜底错误处理器吃掉 | 补 `@Order(-2)`，现在返回 429 + 统一 JSON |
| 3 | Nacos 3.x 启动即退出 | 3.x 强制要求服务端身份标识与 token secret ≥32 字节 | 配置 `identity.key/value` 与 base64 secret |
| 4 | Nacos Derby 内嵌库反复连接超时 | Derby 在本机环境不稳定 | 切换 MySQL 外置存储（也更接近生产） |
| 5 | web-api Feign 调用报 NoFeignClient | 缺 `spring-cloud-starter-loadbalancer`（Feign 的 lb:// 解析依赖它） | 补依赖 |
| 6 | 网关 8000 端口「明明空闲却占用」 | 本机另一项目 uvicorn 占了 8000，处于 Bound 状态，按 `-State Listen` 查不到 | 换 8090；排查经验：查端口用全状态而非只查 Listen |

## 5. 已知限制

- 多实例下 WebSocket 定向推送、Sentinel 规则持久化到 Nacos、网关层压测数据采集，留到 P4。
- `sys_user` 只有 admin 一个种子用户（BCrypt 加密存储），权限模型仅 ADMIN/USER 两级。

## 6. 启动顺序

```
1. MySQL / Redis（系统服务）
2. scripts\kafka-start.ps1
3. scripts\nacos-start.ps1
4. em-device-access → em-data-process → em-web-api → em-gateway
   （或 scripts\start-all.ps1，内部已处理 SERVER__PORT 污染）
5. em-simulator 127.0.0.1 9000 3 500
```
